## 6. Security considerations addressed

- Runtime role `profile_app` cannot bypass RLS and is not the table owner.
- Client-supplied tenant IDs are not accepted anywhere; context is server-side.
- `apply_tenant` uses transaction-local `set_config` to avoid pool leakage.
- Production config refuses `debug=true` and default development credentials.
- Request IDs are validated for length and echoed only when reasonable.
- Error responses never include stack traces.
- Secrets are excluded from git; `.env.example` contains development values only.
- Container runs as a non-root user.

## 7. Known limitations

- No authentication yet — the login page is an explicit placeholder and accepts
  no credentials.
- No domain tables, RLS policies, or RBAC enforcement until M2.
- Celery proves wiring only; no sync/score/rank tasks.
- Frontend has no component tests yet.
- Compose uses development credentials by design; production must supply real
  secrets and a non-superuser migration role.
- `httpx` TestClient emits a third-party deprecation warning (not our code).
