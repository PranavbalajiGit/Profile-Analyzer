# Development Guide

## Prerequisites

| Tool | Version used |
| --- | --- |
| Python | 3.12+ |
| Node.js | 22+ |
| Docker Desktop | 26+ (for PostgreSQL and Redis) |
| Git | any recent |

`psql` is **not** required locally — it runs inside the container.

---

## Quick start (Docker)

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

That starts PostgreSQL, Redis, the API, the Celery worker, and Beat. The API
container runs `alembic upgrade head` before starting.

Then:

| URL | Purpose |
| --- | --- |
| http://localhost:8000/api/v1/health | Liveness |
| http://localhost:8000/api/v1/health/ready | Readiness (checks PostgreSQL) |
| http://localhost:8000/api/docs | OpenAPI UI |
| http://localhost:5173 | Frontend dev server (run separately) |

Stop services:

```powershell
docker compose down          # keep data
docker compose down -v       # also delete the database volume
```

## Backend (local process)

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

# Apply migrations (requires the postgres container)
.\.venv\Scripts\alembic.exe upgrade head

# Run the API
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

The app connects as `profile_app` (restricted role); Alembic connects as
`profile_owner` (schema owner). Both URLs come from `.env`.

---

## Frontend

```powershell
cd frontend
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build
```

Vite proxies `/api` to `http://localhost:8000` in development.

---

## Tests and lint

```powershell
cd backend
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\ruff.exe check app tests
```

The suite does not require a running database: readiness is tested with a
patched probe, and migrations are verified in Alembic's offline SQL mode.

---

## Database access

```powershell
# Interactive shell as the schema owner
docker compose exec postgres psql -U profile_owner -d profile_analyzer
```

Create a new migration after changing models:

```powershell
cd backend
.\.venv\Scripts\alembic.exe revision --autogenerate -m "describe change"
.\.venv\Scripts\alembic.exe upgrade head
```

Always review autogenerated migrations before committing them.

## Troubleshooting

- **`error during connect ... docker_engine`** — Docker Desktop is not running.
  Start it and wait for the engine.
- **`connection refused` on migration** — the `postgres` container is not
  healthy yet. `docker compose ps` shows health.
- **`profile_app` cannot see rows** — expected once RLS policies exist: the
  transaction must call `apply_tenant(session)` before querying.
- **Port 5433 already in use** — change the mapping in `docker-compose.yml`
  and both database URLs in `.env`.
