# Development Guide

## Prerequisites

| Tool | Version used |
| --- | --- |
| Python | 3.12+ |
| Node.js | 22+ |
| Docker Desktop | 26+ (for PostgreSQL and Redis) |
| Git | any recent |

`psql` is **not** required locally — it runs inside the container.

---

## Quick start (Docker)

```powershell
Copy-Item .env.example .env
docker compose up -d --build
```

That starts PostgreSQL, Redis, the API, the Celery worker, and Beat. The API
container runs `alembic upgrade head` before starting.

Then:

| URL | Purpose |
| --- | --- |
| http://localhost:8000/api/v1/health | Liveness |
| http://localhost:8000/api/v1/health/ready | Readiness (checks PostgreSQL) |
| http://localhost:8000/api/docs | OpenAPI UI |
| http://localhost:5173 | Frontend dev server (run separately) |

Stop services:

```powershell
docker compose down          # keep data
docker compose down -v       # also delete the database volume
```

## Backend (local process)

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"

# Apply migrations (requires the postgres container)
.\.venv\Scripts\alembic.exe upgrade head

# Run the API
.\.venv\Scripts\python.exe -m uvicorn app.main:app --reload --port 8000
```

The app connects as `profile_app` (restricted role); Alembic connects as
`profile_owner` (schema owner). Both URLs come from `.env`.

---

## Frontend

```powershell
cd frontend
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build
```

Vite proxies `/api` to `http://localhost:8000` in development.

## Tests and lint

```powershell
cd backend
.\.venv\Scripts\ruff.exe check app tests alembic scripts
.\.venv\Scripts\python.exe -m pytest
```

The unit suite needs no database. The integration suite needs a dedicated test
database and skips when the variables are absent. Create the database once:

```powershell
docker compose exec postgres createdb -U profile_owner profile_analyzer_test
```

Then run the full suite:

```powershell
$env:TEST_DATABASE_URL = "postgresql+psycopg://profile_app:profile_app@localhost:5433/profile_analyzer_test"
$env:TEST_MIGRATION_DATABASE_URL = "postgresql+psycopg://profile_owner:profile_owner@localhost:5433/profile_analyzer_test"
.\.venv\Scripts\python.exe -m pytest
```

The fixtures apply migrations with `profile_owner`, create per-test tenants, and
reset data between tests. Do not point these at the development database.

Frontend:

```powershell
cd frontend
npm run build       # tsc --noEmit + vite build
```

## Seed data and development accounts

After migrations, create deterministic synthetic data:

```powershell
cd backend
.\.venv\Scripts\python.exe scripts\seed_dev.py
```

The script is idempotent and refuses to run when `APP_ENV=production`. It seeds
two colleges (`NFIT`, `WCET`), three departments, two batches per department,
an admin, a placement coordinator, two mentors with batch assignments, and three
students per college, plus a platform `SUPER_ADMIN` homed in `NFIT`.

| Account | Role | College |
| --- | --- | --- |
| `admin@nfit.example.edu` | COLLEGE_ADMIN | NFIT |
| `placement@nfit.example.edu` | PLACEMENT_COORDINATOR | NFIT |
| `mentor.cse@nfit.example.edu` | MENTOR (CSE 2023–2027) | NFIT |
| `mentor.ece@nfit.example.edu` | MENTOR (ECE 2023–2027) | NFIT |
| `student1@nfit.example.edu` … `student3` | STUDENT | NFIT |
| `superadmin@platform.example.edu` | SUPER_ADMIN | NFIT (platform) |

The same `admin@wcet.example.edu`, `mentor.cse@wcet.example.edu`, … accounts
exist for `WCET`. Password for every seeded account: `DevPassw0rd!2026`.
Sign in with the institution code `NFIT` or `WCET`.

All identities and data are synthetic. Never load real student data into a
development or test database.

## Database access

```powershell
# Interactive shell as the schema owner
docker compose exec postgres psql -U profile_owner -d profile_analyzer
```

Create a new migration after changing models:

```powershell
cd backend
.\.venv\Scripts\alembic.exe revision --autogenerate -m "describe change"
.\.venv\Scripts\alembic.exe upgrade head
```

Always review autogenerated migrations before committing them.

## Troubleshooting

- **`error during connect ... docker_engine`** — Docker Desktop is not running.
  Start it and wait for the engine.
- **`connection refused` on migration** — the `postgres` container is not
  healthy yet. `docker compose ps` shows health.
- **`profile_app` cannot see rows** — expected once RLS policies exist: the
  transaction must call `apply_tenant(session)` before querying.
- **Login returns 401 for a seeded user** — the institution code must match the
  user's college (`NFIT` or `WCET`), and the seed script must have been run
  against the same database the API uses.
- **Integration tests skip** — `TEST_DATABASE_URL` and
  `TEST_MIGRATION_DATABASE_URL` are not set in the current shell; see
  [Tests and lint](#tests-and-lint).
- **Port 5433 already in use** — change the mapping in `docker-compose.yml`
  and both database URLs in `.env`.
